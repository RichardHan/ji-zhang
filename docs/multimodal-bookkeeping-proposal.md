# 多來源記帳提案

本提案只定義需求與驗收條件，不修改 APK。現行 APK 可手動輸入，或把輸入框的文字送到 OpenRouter 解析、確認後寫入 Google Sheets。手機鍵盤的語音輸入可代替打字（視鍵盤而定），但不等於 App 支援錄音或語音辨識。現行 Google 登入也未授權讀取 Gmail。

## 使用情境

| 來源 | 期望行為 |
| --- | --- |
| 語音 | 在 App 按一下開始口述；顯示可修改的逐字稿，再從一句話拆出一筆或多筆交易。 |
| 拍照 | 拍攝或選取收據／發票照片，帶出商家、日期和實付總額。模糊或辨識不到時，保留圖片預覽並標出缺漏欄位。 |
| 影片 | 錄製或選取短片，從有效畫面與語音辨識交易資訊；同一張收據出現在多個畫面時只產生一筆候選。 |
| 地點停留 | 使用者主動開啟後，從符合條件的停留產生「可能有消費」的提醒。只提供地點、時間等可確認資訊，不猜金額、不自動入帳。 |
| Gmail 帳單 | 從使用者選取的郵件擷取期間、應繳金額及到期日。應繳不代表已付款；只在使用者確認實際付款後記帳。 |
| Gmail 發票 | 讀取選取的發票郵件或附件，擷取發票號碼、商家、日期、金額；未確認付款時維持候選。 |
| Gmail 信用卡消費通知 | 擷取選取通知的商家、金額、幣別和時間，保留交易／取消／退款的區別。信用卡月結帳單不應把明細再算一遍。 |
| 電子發票／收據 | 先支援讀取使用者提供的電子檔、分享內容或台灣電子發票 QR Code；擷取可取得的發票號碼、商家、日期、金額。載具或發票平台直接同步不預設可用，另確認官方 API、資格和授權。 |

## 共用規則

- 所有來源先進同一個待確認清單：顯示來源、擷取欄位及不確定的資料；使用者可修改、略過或確認，確認才寫入 Google Sheets。不猜缺少的金額、幣別或日期。
- 用來源識別碼處理同一封郵件、同一張發票或同一批次的重試。跨來源以發票號碼或商家、金額、幣別、時間比對；看起來重複時提示合併或保留，不自行合併兩筆可能獨立的交易。
- 在功能使用時才請求所需權限；定位預設關閉，只保留產生提醒所需的資料。Gmail 先做使用者選取或分享的匯入，不先要求讀取整個信箱；若要直接同步，再評估 OAuth 權限、Google 驗證及資料處理限制。
- 原始音訊、影像、影片、郵件附件與定位軌跡不預設寫入帳本或上傳 AI。若辨識需要第三方處理，先說明會傳送哪些資料及送往何處，由使用者選擇；帳本只保留必要欄位與去重所需的來源識別資訊。

## 建議順序與驗收

1. **語音、照片與電子收據**：先以口述「昨天午餐 120，搭車 180」、一張收據照片及一張電子發票驗證待確認流程。取消、拒絕權限或辨識失敗時不新增帳目。
2. **Gmail 三種來源**：用選取的水電帳單、發票和刷卡通知驗收。同一筆消費同時有收據、發票郵件及刷卡通知時，提示為疑似重複；未付款帳單不計入支出。
3. **影片與停留提醒**：同一收據跨畫面只產生一筆候選；一次符合條件的停留只出現提醒，不直接新增帳目。關閉定位後不再收集停留資料。

各階段共用驗收：未確認前 Google Sheets 無新交易；同一筆確認後重試不重複入帳；既有手動和文字記帳流程仍可用。
